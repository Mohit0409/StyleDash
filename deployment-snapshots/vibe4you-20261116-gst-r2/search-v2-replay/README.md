# Offline Search V2 -> Search V2 Relevance R2 release-chain replay

**This is not a production deployment tool.** It cannot connect to or
change Ubuntu, GitHub main, purchases, customer accounts, or tax records.

Command from the isolated StyleDash repo (requires npm ci and Python):

    py -3.12 scripts/replay_compiled_search_v2_r2.py

This tool recreates **both historical compiled JS release transformations**.
All generated files live only in a disposable OS-temp working directory.

## Actual reproducible stages

1. Start with the SHA-256-pinned public, already compiled V4Y-055 R3
   asset family: 53 JavaScript modules plus its homepage index.html
   (54 inputs). This is archived under base-v4y055-r3/ and is NOT
   React/TSX source.
2. Recompile the original Search V2 bridge from its archived editable
   TypeScript source and helper TS modules using esbuild 0.21.5
   (IIFE, minified). Byte SHA-256 equals the historical bridge.
3. Apply guarded, exact single-anchor public compiled patches for
   autocomplete, product scoring, store matching and relevance sorting.
   Relink all 53 compiled modules from V4Y-055 to Search V2.
   Validate **54/54 exact output SHA-256 hashes** against the archived
   first release's guarded package manifest.
4. Recompile the Search V2 R2 bridge from
   scripts/relevance-r2-runtime-bridge.ts using the current recovered
   editable Search V2 R2 source modules. Its byte hash matches the
   archived R2 bridge.
5. Apply the guarded R2 relevance corrections: canonical brand
   presentation, case-insensitive filter persistence, search runtime
   bridge, and relink all 53 modules. Validate **54/54** final package
   SHA-256 hashes against the historical R2 guarded release manifest,
   AND compare all 54 generated bytes against the **current live
   frontend-runtime/** snapshot captured read-only from Ubuntu.

Original archived behavior included mixed CRLF/LF handling:
the V1 initial module-copy retained raw bytes, while subsequent
Path.read_text() operations performed universal-newline conversion.
The replay implements this intentionally, preventing Windows/Linux
hash drift. All source and output hashes are pinned in replay-inputs.json
and in scripts/replay_compiled_search_v2_r2.py.

## What this proves

- The historical public compiled V4Y-055 R3 baseline is retained
  with byte-perfect integrity.
- Both editable search runtime bridges compile exactly.
- The **Search V2 -> R2 release patch and module relinking are
  independently reproducible**, not just archived ZIP copies.
- The final R2 JS module family and homepage were correctly captured
  as running public production artifacts.
- Build/output validation requires esbuild v0.21.5, rejects missing
  anchors or changed hashes, and writes no persistent output.

## What is NOT yet proven

- A React/TypeScript source-only build of the *earlier* 54-file
  V4Y-055 R3 compiled baseline. The 61-file intermediate Vite build
  from current Search R2 sources is a separate source-recovery track,
  and is NOT the same as the historical R3 release family.
- Source-based builds for separately installed GA4, Ads, CSS, review
  UX, mobile, cache, PWA and other overlays on the public homepage.
- Browser-level authenticated Search/Checkout/Admin/review-photo
  end-to-end behavior for an eventual new source release.
- Complete production manifest coverage: 10 publicly served PWA/CSS
  resources are present and return HTTP 200 but do not appear in the
  existing pinned production integrity manifest.

No production mutation, live test payments, customer data, taxes,
private keys, live credentials or user photos are included.


## Earlier V4Y-046 -> V4Y-056 R13 input replay

v4y046-to-r13/ stores the SHA-pinned 54-file public compiled V4Y-046
baseline, original R13 Python patcher, and exact historical backend
code candidate. scripts/replay_v4y046_to_r13_offline.py reproduces the
56-file R13 candidate plus its candidate.sha256 checksum manifest.
The 54 resulting storefront files equal the later R13 -> R3 input.

This extends compiled release-chain replay backwards; it does not
recover the original V4Y-046 bundle from editable React source.
